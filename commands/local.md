Local SEO baseline. Load `references/local-seo.md` from the **hiveku-seo-agency** skill (Play L1) before running this.
1. Context: `account_context_get({ domain: "seo" })` - service area, the real business name, brand voice, and who is allowed to speak publicly. Then `seo_connections_list` for the GBP `connection_id`s (platform `google_business_profile`).
2. Free DB reads first, all of them: `seo_gbp_listing({})` with no `connection_id` returns one row per connection - sort by `score` ascending and work the bottom quartile. Read `items` (which weights are absent, which are `unknown` and therefore renormalized out of the denominator), the NAP block, verification and duplicate status, `score_history`, and snapshot freshness. Over 26 hours old is four missed cron ticks: stale, not fact.
3. `seo_gbp_overview({ connection_id, days: 90 })` per location - insights totals and trend plus review count, average rating and unreplied count in one cheap call.
4. Live Google calls, ONE pass per location, never looped: `seo_gbp_attributes({ connection_id })` (read `audit.missing`), `seo_gbp_media({ connection_id })` (audit for a COVER, a LOGO, EXTERIOR/INTERIOR coverage and photo recency - Play L8), `seo_gbp_services({ connection_id })` (the public service menu that feeds Google's services filters - Play L9). A `gbp_quota_exceeded` error means wait a minute and stop looping; `gbp_quota_not_approved` means the Cloud project never passed Google's access review and waiting cannot help.
5. `seo_citations_get({})` - free, DB-only, one row per active GBP connection; `audit: null` means never audited. Do NOT run `seo_citations_audit` here without asking: it spends DataForSEO credits against the account's monthly research cap with no confirm step of its own, and a 24h cooldown returns 429 with the stored audit anyway. When you do report it, `missing_major` entries with `basis: 'no_signal'` are UNVERIFIED, not "not listed".
6. Local organic: `seo_local_search_performance({ days: 90, source: "all" })`, `seo_local_top_queries` and `seo_local_top_pages` at `{ days: 90, limit: 200 }`, then `seo_local_compare_periods({ days: 180, source: "all" })` for a true 90-vs-90 - these tools halve the window you pass, so pass double what you want. All `seo_local_*` tools are account-scoped: on a two-brand account they blend, with no filter.
7. Output a ranked defect list: listing gaps by weight, unreplied review backlog, missing attributes, missing or stale photos, an empty service menu, inconsistent citations, and the gap between local demand and the pages that exist. Report per location - averaging Listing Scores hides the one location losing the money.
8. Every GBP write is two-step (preview with `requires_confirm: true`, then the identical call with `confirm: true`) and none of them run from this command. Raise each fix as a task instead.
9. Finish every session of work the same way: persist notable learnings to department memory - read the department's current document with `memory_list({ domain: "<dept>" })`, append your note to the `content` it returns, and send the WHOLE merged document to `memory_update({ memory_id, content })`, which REPLACES it (sending only the new note destroys everything that department had accumulated); use `memory_create({ type: "memory", name: "<dept>", content })` only when no entry exists, and keep `<dept>` to a canonical department name (see hiveku-orient), and reflect the work in Hiveku PM: `pm_projects_list` to find the project (it filters only by `status`; `project_type` is named in its description but is NOT in its schema, so the proxy drops it and you filter the returned list yourself), or `pm_projects_create({ name, project_type })` where project_type is one of seo | ppc | marketing | website | app_dev, then `pm_tasks_create({ project_id, title })` (the field is `title`, not `name`), `pm_tasks_update` as it moves, `pm_tasks_complete({ id, summary })` when the loop is closed. Reopen a task closed too early with `pm_tasks_uncomplete`, never `pm_tasks_update`. Hiveku, not this folder, is the source of truth.
